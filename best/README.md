这个作业还挺有意思的，好多数学推导从Q1推到Q2，给出了两种完全不同的、其实也有点相关的解决问题的视角。
Q1主要是进行一个MATLAB代码的完形填空。这个自行车模型其实是在低速状态下对车辆行进轨迹的一种模拟——通过把四个轮子简化成两个，后轮负责驱动，前轮负责航向角，从而大大简化了计算。这一点在我的推导里也有写到。不过一开始我没发现，我把Y的更新里的加号打成了乘号，导致我的车一开始偏移特别大，甚至Q1的第二个小问题里，我只能看到车辆在做一个十字交叉的追踪，完全没有跟上正弦曲线。后来才发现是我打错符号了。
其实整体的数学原理都不算特别困难，主要还是利用求导来找到距离和角速度。这个运动学约束的核心在于抓住“角速度等于角度的导数”这一个物理关系。当然这里有一个重要前提：假设车辆没有侧滑。如果有侧滑的情况，还要额外考虑轮胎模型，这大概就是PPT里提到的横纵向解耦要处理的问题？
另一个关键点是欧拉离散化。因为电脑没法直接处理连续的微分方程，所以必须做离散化。之前ROS作业里用turtlesim画圆也是类似的道理——由于采样时间不连续，画出来的圆不可能真正完美。这里也一样，欧拉离散化本身就带了近似误差，这也是为什么自行车模型只适用于低速场景的原因——速度一高，每一步的累积偏差就会被急剧放大。
Q2其实就是在Q1的基础上做了升级，还是在自行车模型的框架下，但对转向角和自动跟踪的方式做了探究。我选的跟踪器是纯跟踪（Pure Pursuit），实现起来相对直观。这里关键的一步是要把世界坐标系转换到车辆坐标系，这样才能正确算出行进方向和目标点之间的夹角，也就是阿尔法角。然后利用正弦定理建立几何关系，解出前轮转角。
如果说题目一（自行车模型那块）更偏向几何推理，主要是用物理和几何关系来推航向和转向，那机器狗寻优这部分就更偏向数值优化了。从Q1的无约束梯度下降，到Q2带约束的KKT条件，再到Q3的QP标准型，层层递进，确实能看出数学和工程之间的衔接——先理解问题本身，再写成求解器能读懂的矩阵语言。
Q3我最大的问题其实是编译环境，OSQP一直没装上，但核心代码我是写了的，推导也理清了，之后会用MATLAB的quadprog做等效验证。不过好像是git的问题，一直没有吧osqp库的头文件找到。
其实整份作业走下来，最大的感受倒不是某一个数学公式有多难，而是“推导”和“实现”之间的那条沟比想象中宽。纸上算出来的东西再漂亮，落到代码里还是会因为一个符号、一条路径、一个库的版本卡好久。不过反过来说，也正是这种卡顿，让我把每一步拆得更细了——比如欧拉离散化为什么必须要做，纯跟踪里那个阿尔法角到底是怎么来的，KKT条件到底是怎么推导的。这些细节如果不是亲手推一遍、亲手敲一遍、亲手debug一遍，光靠看是看不出来的。
这个作业有意思的地方就在于，它把“几何直观”和“数值优化”两种思维方式放在了一起。自行车模型那块，你得像学高中物理一样画图、找三角形、列正弦定理；到了机器狗这块，又变成了梯度、拉格朗日、矩阵填数。两种思路看起来离得很远，但其实都在解决同一个问题——让一个东西按照你想要的方式动起来。一个是靠几何直觉，一个是靠计算机硬算，各有各的适用范围，也各有各的局限性。之后如果有机会，想把OSQP彻底装通，看看它内部到底是怎么解这个QP的，也算补上这次留的坑。
有关这次ai的使用情况，因为我交的已经算很迟的了，所以也是用了ds（换一下国内的llm试一下手感）帮助我学习
我自己的使用方式大概分三种情况：
第一种是当搜索引擎用。 比如忘记某个函数的参数顺序了，或者某个报错看不懂什么意思，直接丢给AI比翻文档快得多。这种用法我觉得没什么争议，就跟以前用Google一样，只不过现在问得更自然了。
第二种是理解概念。 比如OSQP那部分，我一开始完全看不懂它的接口怎么用，就让AI给我解释P矩阵和q向量分别对应什么。这种场景下AI的优点是能针对我的具体问题给出回答，而不是扔给我一堆文档让我自己找。但我也发现一个问题——AI讲的东西不一定全对，所以关键部分我会再查一下别的来源，或者自己拿笔推一遍验证。
第三种是生成代码框架。 这次的确有让AI帮忙写代码的情况，比如Q3的OSQP求解部分。但我不会直接复制粘贴就跑，而是先看一遍每行在干什么，然后在旁边写注释解释它为什么这么写。这样可以确保即使代码不是我自己一个字母一个字母敲出来的，我也知道它干了什么、为什么这样干。
不过也不是所有代码都能靠AI搞定。这次我踩了一个挺明显的坑——Y的更新把加号写成乘号，AI其实没帮我发现这个问题。因为AI只能看到你给的代码片段，它不会主动跑一遍看看物理上对不对。所以最后还是得靠人自己推一遍、看一遍、跑一遍。这也说明了一些事情：AI能帮你写代码，但它不能替你理解物理。数学推导的合理性最终只能由人来判断。
我比较警惕的一点是，用AI写代码有时候会让人产生"我懂了"的错觉。其实你只是看懂了一段代码的注释，真正的理解是你知道为什么要这样写，以及如果换了条件要改哪里。
总之，AI能显著提升效率，但它不能替代你的思考——至少在现阶段是这样。以后如果可以进车队的话我还是想给自己配置一个cc + ds O(∩_∩)O哈哈~
