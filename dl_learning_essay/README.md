这一篇论文比较精简，我是在知网上通过高级检索（关键字：深度学习，智能驾驶）后再通过引用量的检索找到的。与应用方向比较相关，重在对算法的优化。
我记得在笔试的时候，有一道题目：如果在光照，天气，拍摄条件不好的情况下，应该怎么优化视觉？本文就为在劣势，实际交通状况的优化提供了一种方法：可以在条件没那么理想的情况下进行准确的特征识别和模型学习。
现实环境下，由于交通标志繁多（比赛中也需要识别不同锥桶），可能在目标不明显的情况下（比如光照，天气，运动模糊，遮挡这些原因），特征不明显，不易被识别。但无论是交通标志还是锥桶，其外形，颜色等特征都相对固定。可惜，目前传统方法比较难以同时兼顾鲁棒性和实时性。可以基于这一点的改进开发（优化）一个算法，这个算法应该满足：1.能够在现实光照/天气条件不同的情况下，对交通标志进行合适的识别。或者说，具有较好的鲁棒性。2.计算量适合，不对硬件造成太大的负担。
应该对鲁棒性做一个解释：鲁棒性（Robustness）就是对于在噪音环境下，模型对于正确结果输出能力强弱的衡量（举个例子，L2正则化能让模型对异常数据不那么敏感）。我们之前做的很多作业，比如kmeans中对于簇类超参数的设置，比如线性回归的正则化，再比如深度学习中对于数据的标准化，在层间的标准化以及优化器调整梯度的正则化都是提升鲁棒性的方法。
于是，有一个算法出现了，在CNN，RCNN以及fast-RCNN后，出现了faster-RCNN网络，检测速度快，识别率高，泛化能力强。这完美符合了我们刚才的要求：准确性高，泛化强对应了鲁棒性要求；计算快对应了我们的时间要求。
faster-RCNN的原理大致是：通过将卷积层输出的结果（特征图）传入给两个网络：RPN和检测网络来提升速度。这里面的原理挺有意思的：RPN网络通过对特征图像进行再一次的slide（类似于卷积的操作但有点不同：用一个卷积核在特征图上滑动，然后针对每一个卷积核的锚点（中心点），设计一些不同大小和形状的“框”再进行计算。计算什么呢？计算一下这里面有物体的概率。
这讲起来有点抽象了。举个例子。针对小目标，用 3 种比例：3:10、3:4、1:1。分别计算他们在中间到底有没有有物体，然后输出概率。一个锚点要做两件事：分类：到底是物体还是背景？分别的概率，2个参数；回归：我这个框要有物体，我该往哪里移动，怎么缩放？4个参数。这样，经过概率的筛选，得到一定的物体区域。
ok，我们现在知道哪里有高概率出现物体了。那么我们接下来对于物体的识别就可以只在这些区域进行了。
那我们怎么实现回归这一步呢？这就要用到我们的损失函数了。依旧计算loss然后让loss最小实现回归。
其损失函数如下：
Faster-RCNN 的总损失函数是分类损失和回归损失的加权和：
L({p_i},{t_i}) = (1/N_cls) * Σ_i L_cls(p_i, p_i^*) + λ * (1/N_reg) * Σ_i p_i^* * L_reg(t_i, t_i^*)
其中：
i 是锚点（anchor）的索引（每个滑动窗口位置有多个锚点）
p_i 是预测出的概率（这个东西是目标还是背景）
p_i^* 是真实标签（1 表示有物体，0 表示没有）
t_i 是预测的边框偏移量（4个值）
t_i^* 是真实的边框偏移量
N_cls 和 N_reg 分别是参与分类和回归的锚点数量，用来归一化
λ 是一个平衡系数（论文里常用10，让回归损失和分类损失量级差不多）
分类损失用的是二分类交叉熵：
L_cls(p_i, p_i^) = -log[ p_i * p_i^ + (1 - p_i^*) * (1 - p_i) ]
说白了就是：如果是正样本（有物体），就让预测概率 p_i 越大损失越小；如果是负样本（背景），就让 1-p_i 越大损失越小。很直觉。
回归损失用的是 smooth L1：
L_reg(t_i, t_i^*) = smooth_L1(t_i - t_i^*)
其中smooth_L1(x) =（两种情况）
0.5 * x^2, 如果 |x| < 1
|x| - 0.5, 其他情况
那为什么不用平方损失（L2）呢？因为平方损失对离群点太敏感，梯度可能爆炸。smooth L1 在误差小时平滑收敛，误差大时梯度固定为 ±1，更稳定——又是鲁棒性的体现。
那 t_i 和 t_i^* 到底是什么？它们是边框的“偏移量”，不是直接预测坐标。这定义了从锚框到预测框的变换：
t_x = (x - x_a)/w_a, t_y = (y - y_a)/h_a
t_w = log(w/w_a), t_h = log(h/h_a)
t_x^* = (x^* - x_a)/w_a, t_y^* = (y^* - y_a)/h_a
t_w^* = log(w^/w_a), t_h^ = log(h^*/h_a)
x, y, w, h 是预测框的中心坐标和宽高，带 a 下标的是锚框的值，带 * 的是真实标注框的值
网络不直接学坐标，而是学“相对偏移量”，更容易收敛。

接下来就是这篇文章很特别的一点：他不像我们之前作业里设计的cnn一样，只是把图片卷积池化，输出特征图，不关心到底这张原图片里每个位置到底是什么，只有特征识别。而roi，就是我们刚才识别出来的特征区域，我们在特征区域里做的处理更好地知道这个物体是什么，特征又是什么。
那ROI Pooling和一般CNN中池化方面的区别与联系是什么呢？如下：
先说一般 CNN：输入是一张固定大小的图片（比如 224×224），经过一堆卷积和池化后，得到一个小尺寸的特征图（比如 7×7×512），然后直接拉直送入全连接层。整个过程，没有“候选区域”这个概念，全连接层接收的是整张图的特征。
Faster-RCNN里的ROI Pooling就不一样了。假设RPN告诉了我们大概300个位置可能有物体，但这些位置在特征图上的大小各不相同（有的 2×3，有的 5×7）。可是检测网络的全连接层要求输入固定长度（比如 4096 维），怎么办？
ROI Pooling 就是干这件事的：对每个候选区域，在特征图上把它扣出来，接着把这个区域均匀分成 n*n个小格子，每个格子里取最大值（很熟悉吧，这就是池化的操作Max Pooling）于是不管原来的区域是什么形状，最后都变成n*n的固定大小，就能喂给全连接层了。
所以到底有啥区别？在此总结一下：
普通池化（Max/Avg Pooling）：对整张特征图进行下采样，输出还是整张图（只是尺寸变小）
ROI Pooling：对多个不同大小的候选区域分别进行池化，输出多个固定大小的特征块
联系：本质上都是池化操作（取最大值或平均值）都无训练参数，只是数据处理手段
这就是faster-RCNN的整个过程。下面是原文对整个算法实现过程的描述：
Ｆａｓｔｅｒ－ＲＣＮＮ算法的具体实现步骤如下：
步骤１：输入任意大小的图片数据；
步骤２：利用卷积神经网络对样本图像特征进行提取；
步骤３：ＲＰＮ网络共享卷积特征，生成建议区域，通过Ｓｏｆｔｍａｘ函数判断锚点属于待检测目标或者背景；
步骤４：利用边框回归修正锚点，并获得准确的目标区域；
步骤５：ＲＯＩ　Ｐｏｏｌｉｎｇ整合输入的卷积特征和目标区域，获得目标区域的特征图；
步骤６：检测网络全连接层利用目标区域的特征对目标类别进行判定；
步骤７：再次使用边框回归获取目标更加精确的位置；
步骤８：输出检测和分类结果
有了算法，接下来就是实现了。过程和我们的作业还挺像的。原文说，对这个算法的实现主要分为离线训练和在线识别两部分。获取待检测交通标志的训练数据后，首先选取合适的预训练模型，然后优化网络结构参数使其适应小目标检测，最后通过离线训练得到检测模型。将待检测交通标志样本图片输入到检测模型中，可自动得到最终的检测结果。
如果是车队任务要用这个，我们应该会预先获取道路真实情况，然后进行分类，划分训练集/测试集/验证集，再对应训练。然后低速跑动，逐步加速。
我们来学习一下文章的训练过程和验证过程：
先说数据集。他们用的不是自己拍的照片，是德国的交通标志数据集（GTSD）。里面900张图，每张1360×800，有43类交通标志。但900张其实不太够训深度学习模型，容易过拟合。所以作者干了一件事：调对比度、亮度、色调，把900张扩成了1800张。这个操作叫数据扩增，也是一种正则化手段，前面提过。
然后按VOC2007的格式整理：图片放一个文件夹，标签（xml）放另一个，再搞个txt列表告诉程序哪些是训练集哪些是验证集。训练集1300张，验证集400张，测试集另外留了100张。我们做作业实现的时候应该也有类似这样的划分。
选预训练模型的时候有个细节。Faster-RCNN官方给了三个选择：ZF（小网络）、VGG_CNN_M_1024（中）、VGG16（大）。按理说大网络效果更好，但作者选的是最小的ZF。为啥？因为他们要检测的交通标志很小（16×16到128×128）。网络越深，最后一层特征图上一个点对应原图的区域（感受野）就越大，小目标的位置信息容易被“抹平”。再加上大网络吃显存、训练慢，不划算。所以选了ZF，浅层，保留小目标位置信息，训练也快。
然后做了一组针对性优化。原本Faster-RCNN的锚点（anchor）尺度是128²、256²、512²，宽高比1:2、1:1、2:1，那是为了检大物体。交通标志在1360×800的大图里占的像素很少，所以作者把锚点宽高比改成了3:10、3:4、1:1，专门适配小目标。还有一个阈值：原来低于16×16的目标直接不检测，作者把它改成了10×10。硬是把检测下限往下拉了一截。
超参数方面：批量大小（batch size）设成64，再多显存就不够了。学习率初始0.01，动量0.9，每3000次迭代降一次学习率。训练方式选“近似联合”，就是端到端一起训RPN和检测网络，省时间。
训练了9000次迭代，每3000次保存一个模型。看损失曲线：总损失从高点快速掉到0.1~0.2，分类损失掉到0~0.1，RPN那边的分类和回归损失也都掉到0.1以下。说明模型学进去了，没有崩溃。
验证集上mAP（均值平均精度）是71.27%。单张图片检测大概0.4秒，约合2.5帧每秒。对于交通标志检测这个场景，够用了，毕竟车也不是非得100帧才叫实时。
后面他们还测了各种恶劣环境：光照影响、阴影遮挡、高速运动模糊，mAP都能在0.7上下浮动。拿去瑞典的数据集上直接测（没微调），mAP也有0.703，泛化能力确实不错。
最后跟SSD、多视窗SSD、R-FCN比了一下，本文的ZF+Faster-RCNN跑出0.713，比第二名的0.650高一截。虽然没有碾压，但在小目标检测这个难题上算是站稳了。
以上就是这篇论文的核心实现和实验。回头看看，跟我们之前做作业的思路其实差不多：准备数据（已帮忙准备好）、扩增、选模型、调超参数、看损失曲线、算精度。不同的是人家调的是锚点比例和阈值这种目标检测特有的东西。如果我们要做锥桶检测，完全可以参照这套流程，把数据集换成自己的锥桶照片，锚点比例再根据锥桶的实际长宽比微调一下，应该能跑起来。应该吧QAQ

其实接着这篇论文，我还想讨论一下有关faster-cnn的后续发展。其实这已经和这篇论文有点没关系了，当然，读到这里，我也会有一些自己的思考。
首先，这篇论文发表于2020年。从当时的角度来看，针对交通标志这种小目标检测任务，对Faster-RCNN进行针对性的优化确实是一个不错的方案。通过调整Anchor比例、降低最小检测目标尺寸以及选择更加适合小目标检测的ZF网络，成功提升了检测精度和鲁棒性。从实验结果来看，在复杂光照、遮挡以及运动模糊环境下依旧能够保持较好的识别效果，这一点是比较值得肯定的。
但是从今天的角度再回头去看，也能发现一些局限性。
首先是检测速度的问题。虽然文中提到单张图片检测时间约为0.4秒，折合约2.5FPS，在当时交通标志检测场景下已经能够满足一定需求。但是如果放在智能驾驶或者机器人实时控制任务中，这个速度显然是不够的。对于自动驾驶来说，车辆每秒钟都在移动，如果目标检测延迟过大，那么检测结果可能已经落后于真实场景。后续出现的YOLO系列算法，其实很大程度上就是在解决这个问题。通过单阶段检测网络直接完成目标定位和分类，大幅提升了检测速度。
其次是Faster-RCNN本身的结构问题。虽然RPN能够有效筛选候选区域，减少无效计算，但整个算法本质上仍然属于两阶段检测器。先生成候选框，再进行分类和回归。这种设计虽然提高了精度，但同时也增加了计算复杂度。在计算资源有限的嵌入式设备上部署时，往往不如后来的YOLO系列方便。
另外还有一个让我比较感兴趣的问题。本文针对交通标志进行了Anchor比例调整，使其更加适合小目标检测。从结果来看确实有效。但这种方法本质上还是一种人工经验优化。换句话说，作者已经提前知道交通标志的大致形状和尺寸分布，所以才能设计出更适合的Anchor。如果面对新的任务，比如锥桶检测、行人检测或者其他目标检测任务，可能又需要重新设计Anchor参数。因此我在想，能不能让网络自动学习这些候选框的形状，而不是依赖人工设计。后来查资料的时候发现，Anchor-Free系列算法其实就在尝试解决这个问题。
此外，文章中使用的数据集规模其实并不算特别大。原始数据只有900张图片，即便经过数据增强扩展到1800张，其数据量相比现代深度学习任务仍然偏小。因此虽然实验结果不错，但模型对于更加复杂道路环境的适应能力可能还需要进一步验证。例如极端天气、夜间环境或者不同国家交通标志体系下的泛化能力，仍然值得进一步研究。
不过总体来说，这篇论文最大的价值并不一定是提出了一个革命性的算法，而是在实际工程背景下展示了如何针对具体任务分析问题、修改网络结构、调整超参数并验证实验结果。这种完整的工程实现思路，对于我理解目标检测任务和后续开展相关项目具有很大的参考意义。
同时也让我产生了一个新的问题：为什么后来目标检测的发展路线逐渐从Faster-RCNN转向YOLO？Anchor机制后来为什么又逐渐被Anchor-Free方法替代？这些问题或许也是接下来继续阅读相关论文时值得重点关注的方向。
